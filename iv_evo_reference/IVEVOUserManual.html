Abstract

IV-Evo is a new series of indicators for a various models of cars.

IV-Evo consists of ESP32C3 microcontroller and display, and is able to connect to a car wiring to read parameters, and display them in a convenient way.

Features:

  • 160x80 pixels IPS display
  • Tempered glass front panel
  • ESP32C3 MCU
  • Wi-Fi, Bluetooth LE support
  • Lua-configurable and 3rd party apps support
  • Support of raster graphics (JPG, PNG, BMP)
  • Support of simple 3d and 2d animation
  • For Golf, Jetta, Polo and Audi cars and also for LADA cars.

IV-Evo Gear indicator

IV-Evo Gear is a gearbox selected gear indicator, supporting R, 1,2,3,4,5 gears

The idea beyond the indicator is to calculate the gear based on current speed and RPM. Reverse gear is shown if the sensor has positive input on one of inputs.

Device is operated with Bluetooth, and you’ll need Digifiz Next unit in your car for correct operation. Also, speedometer and RPM, as well as gear table should be calibrated to match.

To use IV-Evo Gear, you need to just power it up using pins 1 and 7 (KL30 pin - connect to KL15, ignition power, pin 7 - connect to ground) After that, device will power up and show “-” - meaning that gear is not selected.

Device takes its data from Bluetooth channel from Digifiz Next, so right after the starts its search for Digifiz Next unit.

You’ll need to update your Digifiz Next to a firmware not less than 1.0.14 version, which  introduces BLE streaming of several parameters.

Installation guide:

  1. Install Digifiz Next v1.0.14 to your dashboard
  2. Connect power +12V KL15 ignition and car masse to pin 1 and pin 7 accordingly
  3. Power on in a boot mode(press boot button shortly after turn on) - QR Code will appear. Scan it from you phone and connect to the dashboard.
  4. Select application and sensor - “iv_gear” and “volts1”, save selection
  5. Restart by ignition off and on
  6. Preliminary installation is complete!

After that, you’ll need to perform a tuning of parameters on Digifiz Next cluster Wi-Fi control panel.

  1. First of all, calibrate your speed using GPS speed from your phone, use speeds like 80-100 kmh as reference for a calibration.

The parameter for speed calibration is on the Settings page.

  1. After that, calibrate RPM setting by using the same settings page. The correct calibration values are, normally, 1500, 3000 and 400 for some gasoline engines and the last one - for the Diesel engines.

IV-Evo Lambda

For IV-Evo Lambda the connection is somewhat more complicated.

It is important that connection to stock Golf 2 lambda sensor is not possible

Lambda sensor measurement should be done with 2 lambda sensors installed in the car.

There are two types of Lambda sensors:

Narrowband Oxygen Sensor:

  • Operation: Measures only whether the air-fuel mixture is rich or lean.
  • Output: Produces a voltage between 0.1V (lean) and 0.9V (rich), without detailed information on the exact air-fuel ratio.
  • Use: Common in older vehicles for basic emissions control.

Wideband Oxygen Sensor:

  • Operation: Provides precise measurements of the actual air-fuel ratio over a wide range, not just rich or lean.
  • Output: Delivers a linear signal, giving the engine control unit detailed feedback to optimize fuel injection.
  • Use: Found in modern vehicles for more accurate fuel management and emissions control.

The problem is that narrowband sensors are not applicable for most of custom engines and carburetors, only wideband ones. And they are more advanced, require more control operations. The indicator itself cannot control wideband sensor, and works directly only with narrowband sensors(needs to be calibrated though)

However, installation of wideband sensor is possible and recommended. For wideband sensor we do recommend Bosch LSU 4.9 sensor, which should be accompanied with supported wideband controller:

  • SLC Free
  • DIY-EFI TinyWB Wideband controller
  • Sigma Lambda Controller Free 2
  • rusEFI wideband lambda
  • Others

After buying such wideband controller please connect it according to its diagram to LSU 4.9 and use analog output (typically, 0-5V, 0.5-4.5 or even 0-1V output) for connection to the IV-Indicator Lambda. Below, on connection diagrams, you can find an example connection.

Appendix 1. Lua API Reference for IV‑Evo

This document describes the Lua runtime model used by the firmware and the currently exposed Lua namespaces (modules) implemented in C.

The goal is to help you write two Lua files:

  • App script (app.lua) with UI logic (drawing on display, handling loop, etc.).
  • Sensor script (sensor/*.lua) that provides measured values through sensor.get(index).

1) Runtime model

App contract

Each app file returns a table (commonly M) with callbacks:

  • M.loop() required
  • M.init() optional
  • M.event(event_type) optional
  • M.cleanup() optional

The firmware loads your app, stores these callbacks, and executes loop() repeatedly. If loop is missing, the app is rejected. On runtime errors, firmware can switch to a fallback app.

Sensor contract

Sensor Lua file should return a table named sensor with:

  • sensor.get(index) returning a numeric value.

The firmware loads the sensor script and stores it globally as sensor, then app scripts call sensor.get(...).

Globals provided by firmware

  • apppath — path to current app folder (useful for loading assets/fonts relative to app location).
  • sensor — table returned by active sensor script.

2) Lua namespaces (modules)

The firmware registers the following Lua modules:

  • display
  • system
  • onewire
  • nvs
  • ble

Load them in Lua with require("module") (or via pcall(require, "module") for optional usage).

3) API reference

display

  • display.loadimg(path) -> img_handle|nil
  • Decodes image and returns handle (integer-like pointer).
  • display.loadfont(path) -> font_handle|nil
  • display.free(handle)
  • Frees image/font allocated by loadimg / loadfont.

Frame control

  • display.fill(color)
  • Fills entire screen.
  • display.update()
  • Flushes frame and clears screen to black afterwards.

Drawing primitives

  • display.drawimg(img, x, y)
  • display.string(font, x, y, text, color)
  • display.fillrect(x, y, width, height, color)
  • display.drawline(x1, y1, x2, y2, color)
  • display.drawcircle(x, y, r, color)
  • display.drawfillcircle(x, y, r, color)
  • display.drawroundrect(x1, y1, x2, y2, r, color)
  • display.drawarrow(x0, y0, x1, y1, w, color)
  • display.drawfillarrow(x0, y0, x1, y1, w, color)
  • display.drawpolygon({x1, y1, x2, y2, ...}, color)
  • Even count of coordinates required (at least 4 elements).

4) Example #1 — Simple voltmeter app

Below is a minimal app using the same style as existing voltmeter apps (sensor.get(1), font draw, cleanup).

local M = {}

local font = display.loadfont(apppath .. "/../fonts/H24XB.FNT")

local function read_voltage()

    return sensor.get(1)

end

function M.loop()

    local v = read_voltage()

    display.fill(display.BLACK)

    display.string(font, 10, 80, string.format("%2.1f V", v), display.WHITE)

    display.fillrect(10, 120, math.floor((v - 9.5) * 12), 8, display.GREEN)

    display.update()

end

function M.cleanup()

    display.free(font)

end

return M

Notes:

  • display.update() is called once per frame.
  • cleanup() should free loaded resources.
  • Clamp bar calculations in production code (existing apps clamp values to display range).

5) Example #2 — Sensor Lua script (NTC-like)

This script demonstrates reading ADC, enabling pull-up rail, smoothing, and returning processed value.

sensor = {}

local filt = 0.0

function sensor.get(i)

    i = i or 0

    system.V2_pullup(1)

    local raw = system.adc_ch(i)

    filt = filt + (raw - filt) / 10.0

    -- Example transform (replace with your real calibration/math):

    local value = filt * 1.0

    return value

end

return sensor

Notes:

  • Keep sensor.get(i) fast; it is called from app loops.
  • You can store calibration in NVS (for example, via nvs.get("key") and tonumber(...)).

6) Practical tips

  • Use pcall(require, "nvs") when NVS access is optional.
  • Build paths from apppath for portable assets (apppath .. "image.jpg", apppath .. "/../fonts/...").
  • Always free display.loadimg / display.loadfont handles in cleanup().
  • If using DS18B20, call onewire.scan18b20() once and onewire.read18b20(index) in loop.
